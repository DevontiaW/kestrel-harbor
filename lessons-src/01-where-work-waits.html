Where does agent work wait?

Picture a small office that just switched on three AI (artificial intelligence) agents to draft customer quotes. The agents are quick. Every quote still goes to one person, the office manager, who checks it before it leaves the building. By Friday the agents are often idle, the manager is buried, and customers are asking where their quotes are.

Nothing is broken; the work is waiting in one place.

Work piles up in front of the step that has more work arriving than time to do it. Every task has to pass through it, so speeding up any other step changes nothing.

The floor in Kestrel Harbor

On the town's agent floor, a new task arrives every {{arriveEvery}} minutes, which is {{arrivalsPerHour}} an hour. Agents research, plan and carry it out ({{agentMinutes}} minutes of work in all, spread over several agents working at once). Then a person reviews it for {{reviewMinutes}} minutes. One task in {{reworkEvery}} fails review once and comes back, so the reviewer sees about {{reviewsPerHour}} reviews an hour. A shift lead also approves every {{approveNth}} task, which lesson 5 returns to.

Predict before you open the answer.

With one reviewer, how many of the {{arrived}} tasks that arrive in an {{shiftHours}}-hour shift get finished? And would a third reviewer help as much as a second?

Show what the model does

With one reviewer, {{one.finished}} tasks finish. At the end of the shift, {{one.reviewQueue}} tasks are still waiting for review. The reviewer is busy {{one.reviewBusy}} of the shift, while the research agent is busy {{one.researchBusy}} and the execution agents {{one.executeBusy}}.

A second reviewer lifts output to {{two.finished}}. A third finishes {{three.finished}}, the same as two. Once review keeps up, more reviewers only sit idle (busy {{three.reviewBusy}}).

A different situation

A clinic uses an AI tool to draft visit summaries, and one nurse signs every one. Each day the tool drafts 40 and the nurse can sign 25, so a stack builds up on the nurse's desk. Next month the tool gets twice as fast. How many summaries reach patients each day, and where does the stack grow?

On Monday

Pick one workflow where AI drafts and a person approves. Count two numbers for one day: how many drafts arrive, and how many the person clears. If arrivals are higher, you have found where your work waits.

All times are illustrative and fixed so the lesson is repeatable. Real work varies, and variation makes lines longer than these. The clinic figures are made-up round numbers for practice.

Build it yourself with AI

Optional. Give this prompt to any AI chat or coding assistant to build a tiny, single-file version of the agent floor. Each later lesson adds one piece to it. It is a starter for learning the idea, not a tool for running a business. Then check its work against the numbers below: an AI can write code that looks right and counts wrong.

The one rule

Work needed per hour versus work available per hour. If a step needs more minutes each hour than its people have, the line in front of it grows every hour.

Here: review needs {{reviewMinutesNeeded}} minutes an hour. One reviewer has 60.

Starter prompt

Build one HTML file with no libraries that simulates a small work queue, one minute at a time, for {{build.minutes}} minutes. Use plain words on screen.

Steps, in order. Each step serves its line in order of when the tasks first arrived in the shift: a task sent back keeps its original place.
- research: {{build.min.research}} minutes, 1 worker
- plan: {{build.min.plan}} minutes, 1 worker
- execute: {{build.min.execute}} minutes, {{build.executeSlots}} workers
- review: {{build.min.review}} minutes, 1, 2 or 3 reviewers (a selector on the page)
- approval: {{build.min.approve}} minutes, 1 worker, only for every {{approveNth}} task (task {{approveEvery}}, {{build.seq.approve2}}, {{build.seq.approve3}}...), after review passes

Every {{reworkNth}} task (task {{reworkEvery}}, {{build.seq.rework2}}, {{build.seq.rework3}}...) fails its first review and goes back to the execute line, then to review again.

Each minute, in this order:
1. Every task being worked gets one minute of work. A task that completes its step joins the line for its next step (or finishes).
2. If the minute is a multiple of {{arriveEvery}} (minute {{arriveEvery}}, {{build.seq.arrive2}}, {{build.seq.arrive3}}...), a new task arrives and joins the research line.
3. Free workers at each step pick up the waiting task that arrived in the shift earliest (not the one that joined the line first).

Show: tasks finished, tasks still in the system, how many wait at each step, and the share of the time each step's workers were busy. Add a button that runs the whole shift.

What "done" looks like

  • One file that opens in any browser, with no internet.
  • A reviewer selector, a Run button, and the counts after the run.
